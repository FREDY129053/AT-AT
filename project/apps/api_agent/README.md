# 🔌 API Testing Module

Подсистема автоматизированного тестирования REST API на основе OpenAPI / Swagger спецификаций.

Модуль предназначен для генерации, выполнения и анализа API-тестов с использованием LLM и property-based тестирования.

---

## ✨ Возможности

* Импорт OpenAPI / Swagger спецификаций
* Автоматический анализ API
* Генерация тест-кейсов на основе спецификации
* Генерация негативных сценариев
* Fuzz-тестирование API
* Тестирование бизнес-процессов
* Поддержка зависимостей между эндпоинтами
* Выполнение тестов в изолированной среде
* Сбор артефактов выполнения
* Формирование отчетов и метрик

---

## 🧠 Как работает

1. Пользователь загружает OpenAPI спецификацию.
2. Система строит внутреннюю модель API.
3. LLM анализирует спецификацию и формирует набор тестовых сценариев.
4. Выполняется автоматическое тестирование API.
5. Собираются результаты и артефакты.
6. Формируется итоговый отчет.

---

## 🧪 Типы тестирования

### Contract Testing

Проверка соответствия реализации API заявленной OpenAPI спецификации.

### Property-Based Testing

Автоматическая генерация большого количества входных данных на основе схемы API с использованием Schemathesis и Hypothesis. Такой подход позволяет выявлять ошибки валидации, нарушения контрактов и необработанные граничные случаи.

### Fuzz Testing

Генерация случайных и пограничных значений для поиска ошибок обработки запросов, внутренних исключений и неожиданных состояний API. Schemathesis использует OpenAPI-схему для генерации как корректных, так и некорректных сценариев тестирования.

### Business Process Testing

Тестирование заранее определенных бизнес-процессов и последовательностей вызовов API.

## 📦 Формируемые артефакты

После завершения тестирования формируются:

```text
allure-results/
junit.xml
report.har
cassette.yaml
results.ndjson
errors.md
```

### Назначение артефактов

| Артефакт         | Назначение                    |
| ---------------- | ----------------------------- |
| JUnit            | Интеграция с CI/CD            |
| Allure Results   | Построение визуальных отчетов |
| HAR              | Анализ HTTP-трафика           |
| VCR Cassette     | Воспроизведение запросов      |
| NDJSON           | Детализированные результаты   |
| Markdown Reports | Описание найденных ошибок     |

## 📊 Результаты тестирования

Подсистема позволяет обнаруживать:

* ошибки валидации входных данных;
* нарушения OpenAPI-контрактов;
* неожиданные HTTP-ответы;
* внутренние ошибки сервера (5xx);
* проблемы интеграции между эндпоинтами;
* ошибки бизнес-процессов;
* некорректную обработку граничных значений.
